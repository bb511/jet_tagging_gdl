# Scripting

The commands that can be run to obtain all the results in this study.
**Please run everything from the repository root.**

The available directories contain the following scripts:

- `experiments/` holds the command catalogues of both data sets, `hls4ml/` and `top_tagging/`, the submitters that run them on a GPU host or NGT pods, and `make_train_catalogues.py`
- `analysis/` contains the scripts that produce the result latex tables and corresponding figures
- `synthesis/` contains the synthesis of the quantised vector-neuron network with alkaid and Vivado

## Command Catalogues

The `run<model>_{search,train,eval}.sh` under `experiments/hls4ml/` are lists of commented-out `python3 src/train.py` and `src/eval.py` blocks.
Those of the five grid rows sit in one directory per feature set, `px_py_pz_e/`, `pt_eta_phi/` and `pt_etarel_phirel/`; those of every other row sit at its root.
Running a file does nothing unless you uncomment the command that you want to be ran.
DeepSets, MLP, JetFormer and Linformer have 21 blocks each, the three constituent counts over the seven regimes.
LorentzNet, PELICAN, LGATr, LLoCA, and vector neurons have embedded symmetries and are run with baseline only: three blocks each.
`runpelican_lorentz_search.sh` carries two: the 150-constituent row is not searched and its experiment config holds the beams-on optimum instead.
JEDI-linear, the comparator from the FPGA literature, runs the seven regimes as the other grid rows do (21 blocks), and every feature-set directory carries its catalogues.

The submitters in `experiments/` parse these files.
You can select entire categories of commands to run with `--only nconst150` or `--only symm_so2`.
You can also target a specific gpu on the machine you are running on by setting `--gpu`.

The hyperparameter studies are ran separately.
The name of a study is automatically derived from its configuration in `configs/hparams_search/hls4ml/<model>_optuna.yaml`.
The `*_train.sh` and `*_eval.sh` scripts are then generated by `experiments/make_train_catalogues.py` from the study databases when completing a study.
These latter scripts contain the best models from those studies.
Do not edit these, always regenerate.

## Pipeline

Here is the whole results pipeline:

```
experiments/hls4ml/<features>/run<model>_search.sh
  |  experiments/submit_search.sh
  v
logs/optuna/hls4ml[/<features>]/<model>.db   the sweeps' only durable record
  |  experiments/make_train_catalogues.py [--features pt,eta,phi]
  v
experiments/hls4ml/<features>/run<model>_train.sh
  |  experiments/submit_train.sh
  v
logs/train/hls4ml[/<features>]/<model>/nconst<N>/<variant>/checkpoint_manifest.json
  |  experiments/submit_eval.sh  (experiments/hls4ml/<features>/run<model>_eval.sh)
  v
results/<features>/results_table_{baseline,augmentation,symm_loss}.csv
  (LorentzNet, the two PELICANs, the two L-GATr-slims, the four LLoCas, the vector neurons and the three moment rows: results/embedded/results_table_baseline.csv;
   the four jet-level rows: results/jet_level/; vn_hgq: results/quantised/)
  |  analysis/compare_to_baseline.py <run table> <baseline table>
  v
results/<features>/deltas_<run>_vs_<baseline>.csv
  |  analysis/make_figures.py --features <features> --deltas <deltas table>
  v
results/<features>/fig_{augmentation,symm_loss}.svg
```

Have a go by running:

```bash
bash scripts/experiments/submit_train.sh --dry-run --only baseline --gpu 0 scripts/experiments/hls4ml/px_py_pz_e/rundeepsets_train.sh
```

## Script Manifest

| File                                   |                                                                                     |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| `experiments/submit_search.sh`         | Optuna drivers of a search catalogue; `--tag`.                                      |
| `experiments/submit_search_ngt.sh`     | Several workers of one study on a pod, through `submit_search.sh`.                  |
| `experiments/submit_train.sh`          | A train catalogue: nohup queue or `--folds` fan-out.                                |
| `experiments/submit_eval.sh`           | An eval catalogue as a nohup queue; warns of a block whose manifest is missing.     |
| `experiments/sweep_status.py`          | Trials against the target, live workers, the command to finish it; `--features`.    |
| `experiments/lib.sh`                   | Shared by the submitters: parser, `--only`, `.env`, GPU pinning, the nohup queue.   |
| `experiments/make_train_catalogues.py` | Studies to `run*_{train,eval}.sh`; `--features`, `--dry-run`.                       |
| `analysis/common.py`                   | Shared by the six: table reading, fold parsing, display names; not a script.        |
| `analysis/compare_to_baseline.py`      | Joins a run table with a baseline table into a deltas table; the reference is free. |
| `analysis/make_figures.py`             | Deltas against a baseline, one figure per regime; `--features <dir> --deltas <p>`.  |
| `analysis/make_baseline_figure.py`     | The absolute counterpart for baseline rows, e.g. `results/embedded/`.               |
| `analysis/make_latex_table.py`         | Results tables to `.tex`, formatting only.                                          |
| `analysis/collect_params.py`           | Parameter and FLOP counts of every main training run, from MLflow; `--out`.         |
| `analysis/compare_outputs.py`          | Clean outputs of two evaluations of the same jets, figure by figure; `--csv`.       |
| `synthesis/synthesise_vn.py`           | A `vn_hgq` export through alkaid, Verilator and Vivado to a `synthesis.csv` row.    |
| `setup.sh`                             | Working directories and `.env`, which it never overwrites.                          |
| `symbolink.sh`                         | `data/`, `logs/`, `outputs/`, `results/` as symlinks per `.env`; destructive.       |
